# Tool 4 — point forecast graph UI — plan (v2)

Status: **draft v2, awaiting review before prototyping.** v1 covered
single-select (one model, one run, one site). v2 folds in the multi-select
spaghetti design and the ensemble view. Nothing here is built yet.

## What this is

A browser tool for the numeric per-site forecasts in `points.parquet` (not
the rendered map PNGs Tools 1–3 browse). Pick model(s) and run(s), click
site(s) on a basemap, pick a quantity, and read the forecast curves in an
in-browser chart — including multi-line "spaghetti" comparisons and ensemble
spread. Rain is never shown (explicit exclusion).

## 1. Data source & schema

`points.parquet` (`src/extract/base.py:PointRow`):

```
model:str  run_init:datetime[UTC]  member:int(-1=deterministic)  site:str
valid:datetime[UTC]  cloud_low/mid/high/total:float|None  temp_c:float|None
provenance:str(native|derived|total_only)  fetched_at:datetime[UTC]
```

Which quantities exist for a (model, run, site) is exactly which of `temp_c`
/ `cloud_total` / `cloud_low` / `cloud_mid` / `cloud_high` are non-null —
that same fact drives the quantity greying-out (§5). Sites: the 29 named
places in `config/placenames.json`.

## 2. Data delivery — per-(model, run) JSON + a small index

**Not one big JSON.** Chunk as one file per **(model, run)**: all 29 sites ×
all valid times × all fields for that single run. Rationale:

- A run is **immutable** once written → its JSON caches forever (long TTL).
  A per-model-all-runs file would cache-bust every time a new run lands.
- **Fetch only what's plotted** — a multi-model comparison needs each
  model's *newest* run, not its whole history.
- Same shape Tools 1–3 already use: a small index manifest + immutable
  per-asset files.

Two artifacts, generated by a new `scripts/generate_tool4_data.py`:

**`tool4_index.json`** — tiny, always loaded first, drives the listboxes and
greying with zero data fetched:
```jsonc
{
  "generated_at": "...",
  "eclipse_t": "2026-08-12T18:30:00Z",
  "models": {
    "gfs": {
      "label": "GFS",
      "kind": "deterministic",             // deterministic | ensemble
      "deterministic_pair": null,          // for ensembles: the paired HRES model id
      "quantities": ["temp","total","low","mid","high"],
      "runs": ["2026080406","2026080400", ...]   // newest first
    },
    "ecmwf_ens": { "label":"ECMWF-ENS", "kind":"ensemble",
      "deterministic_pair":"ecmwf_hres", "quantities":["total"], "runs":[...] },
    ...
  }
}
```

**`<model>/<run>.json`** — loaded lazily, only when a line needs drawing:
```jsonc
{
  "model":"gfs", "run_init":"2026080406",
  "valid": ["2026-08-04T06:00:00Z", ...],       // shared time axis, stored once
  "sites": {
    "Madrid": { "temp_c":[...], "cloud_total":[...], "cloud_low":[...],
                "cloud_mid":[...], "cloud_high":[...] },
    ...
  }
}
```
Timestamps are stored once per file (all sites in a run share the valid-time
axis), not repeated per site.

**Multi-select is a feature of this layout, not a problem:** a spaghetti
plot = "fetch the N selected `(model,run)` files in parallel, merge
client-side, draw." HTTP/2 multiplexes them; each is independently
cacheable; nothing unselected is ever downloaded. A single combined JSON
would be strictly worse (download everything to draw one line).

**Ensemble caveat:** `ecmwf_ens` / `aifs_ens` carry ~50 members, so their
`(model,run).json` is ~50× a deterministic one. Options (decide at build
time): (a) accept the larger file for those two, or (b) split members into
`<model>/<run>.members.json` loaded only when the ensemble view is opened,
keeping the base file to mean+control. Leaning (b) so the common
non-ensemble path stays small.

## 3. Layout (confirmed)

Top row, three across: **[Model listbox] [Run listbox] [Iberia map]**.
Second row, full width: **[quantity selector] + [plot]**. The tool-tab
toolbar (Newest runs / Compare runs / At eclipse / **Point forecast** /
Pipeline) sits above everything, matching Tools 1–3.

Look-and-feel matches Tools 1–3 exactly (verified against their CSS):
monospace (`ui-monospace, "SF Mono", Consolas, …`), warm cream background
`#f6f4ef`, near-black ink `#232320`, warm-gray borders `#d8d4c8`, brick-red
accent `#8b3a2f`, secondary blue `#2f5f8b`, sharp corners. Quantity selector
is a **radio group** styled like their `.quantityGroup` (accent `#8b3a2f`,
unavailable options `disabled`/greyed `#a8a498`), not pills.

Site selection is by clicking a marker on the map (§4). Listboxes are
multi-select for the spaghetti modes (§6).

## 4. The basemap — still the one genuinely new piece

Tools 1–3 bake coastlines/roads/totality into server-rendered PNGs; no
vector geometry reaches the browser today, so a *clickable* site-picker has
no existing precedent. Two options, still undecided:

- **A — client-side vector** (what the `fmi-all-stations` reference does):
  a one-time export of simplified coastline + roads + totality band, clipped
  to the Iberia bbox, from the same Natural Earth data `src/viz/basemap.py`
  already caches, as GeoJSON/SVG paths. Site markers are real SVG/DOM
  elements — trivially clickable, hover-highlightable, and can linked-hover
  with the chart (hover a line → its city's dot lights up, and vice-versa).
- **B — raster + overlay**: one plain basemap PNG (coastlines/roads/totality,
  no data) with the 29 markers as an absolutely-positioned overlay, placed
  via the bbox→pixel math `frame_renderer.py` already has.

Leaning **A** — it's what the reference does and gives linked hover for free,
which matters once there are many lines. Decide before building the map.

## 5. Quantity selector rules

Options: **Temp · Total · Low · Mid · High** (never Rain).

- Greyed/disabled when all-null for the current selection (e.g. `ecmwf_hres`
  has no L/M/H; `ecmwf_ens` has only Total).
- **Temp is exclusive** — choosing Temp clears any cloud selection and
  vice-versa. Never mix temperature and cloud on one plot (standing project
  rule — differently-scaled quantities get their own plots).
- **L/M/H-together** is a quantity option that draws 3 lines per
  (model, run, city) instead of 1.

## 6. Spaghetti / multi-select — one generalized mode

Your three scenarios are the same UI with a different **varying dimension**:

| Scenario | dimension that varies | held fixed |
|---|---|---|
| multi-model, newest runs | **model** | 1 city, 1 quantity, run = each model's newest |
| one model, multi-run | **run** | 1 model, 1 city, 1 quantity |
| one model/run, multi-city | **city** | 1 model, 1 run, 1 quantity |

Generalized design (doesn't force a mode):

- **Multi-select on model / run / city.** Plotted lines = the cartesian
  product of the selections × (1 or 3 for L/M/H).
- **Color / legend by whichever dimension has >1 selection** (the spaghetti
  axis), so lines are distinguishable at a glance.
- **Hover a line → tooltip with its full identity** (model · run · city ·
  level) and its city's map marker highlights (linked hover, if basemap
  Option A).
- **Line-count guard:** past a soft cap (say ~40 lines), show "showing N of
  M — narrow the selection" instead of drawing unreadable mud.

Run selection UX detail: when multiple models are selected, "newest run" per
model is the default; the run listbox is only meaningful when a single model
is selected (the one-model-multi-run scenario) — spec how the run listbox
behaves under multi-model selection during prototyping.

## 7. Ensemble view (needed feature)

For an ensemble model (`ecmwf_ens`, `aifs_ens` — the only two with real
members; `gefs_extended` is control-only here): one model, one run, one
city, one quantity → draw

- **Member spaghetti** — one thin line per perturbed member (~50), the
  spread.
- **Ensemble mean** — one bold curve (mean across members per valid time).
- **Deterministic reference line** — the paired high-resolution deterministic
  model overlaid (`ecmwf_hres` for `ecmwf_ens`, `aifs_single` for
  `aifs_ens`), loaded from *its* `(model,run).json`. Optionally also the
  **control member** (the unperturbed `cf`/`c00` member from within the
  ensemble) — decide during prototyping which one reads as "the main line",
  or show both with distinct styling.

`member` is already in `points.parquet` (`-1`=deterministic, else the member
index), so this is free data-wise — needs confirming which member index is
the control before wiring the control line.

## 8. Charting library

**uPlot**, vendored locally (no CDN, ~51 KB), matching `fmi-all-stations`
exactly — proven at this line count, and its linked-hover / pin-to-compare
interaction is a direct fit for the spaghetti + linked-map-hover design. It
would be Tool 4's own new dependency (no charting lib exists elsewhere in
this project yet); matching a working reference beats picking a new one.

## 9. Serving

No new infrastructure: `scripts/serve_frames.py`'s static file server
already serves the tree with correct caching (`_NO_CACHE_NAMES` keeps
manifests/HTML always-revalidate; immutable assets long-cache). Tool 4's
HTML/JS + `tool4_index.json` + the `(model,run).json` tree land in that same
served tree.

## 10. Still not decided

- Basemap approach (§4, A vs B).
- Ensemble member-file split (§2b).
- "Main line" for the ensemble view: deterministic overlay vs control member
  vs both (§7).
- Run-listbox behavior under multi-model selection (§6).
- Exact soft line-count cap (§6).

## 11. Rollout / prototype sequence

1. `scripts/generate_tool4_data.py` → `tool4_index.json` + `<model>/<run>.json`
   against the rebuilt `points.parquet` (seeding in progress; a handful of
   models is enough to start — full coverage is not a prerequisite).
2. Basemap asset (chosen §4 option) — one-time export.
3. Client: toolbar + listboxes + map markers + uPlot chart, single-select
   first, then multi-select spaghetti, then the ensemble view.
4. Wire into `serve_frames.py`'s tree, verify in browser against real data.

**We can start step 1 as soon as this plan is approved** — the seed already
has `gfs` / `gefs_extended` / `ecmwf_hres`, enough to generate a real index
and a few `(model,run).json` files and evolve the current mockup into a
client that loads them. The remaining models fill in as the seed completes.
